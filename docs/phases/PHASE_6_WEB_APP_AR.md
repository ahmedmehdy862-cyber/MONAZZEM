# المرحلة 6 (شريحة ٢) — تطبيق الويب (Phase 6)

> الفرع: `phase6-web-sync-foundation` (نفس فرع المرحلة 6، كوميت ثانٍ بعد شريحة الخلفية).
> الحالة: **مُنفَّذة محليًا، غير منشورة**. لا تغييرات في نشر Vercel ولا متجر QUBIX ولا تطبيق Android.

## نطاق هذه الشريحة

تأسيس تطبيق ويب عربي صغير يعمل محليًا أولًا، مع مزامنة اختيارية تستخدم `/api/sync` من الشريحة الأولى. لا Supabase، لا نظام دفع جديد، ولا رفع إصدار. البنية الحالية (`manifest.webmanifest` و`sw.js` والصفحة الرئيسية) كانت توفّر بالفعل أساس PWA، فاكتُفي بتوسيعه بدل إعادة بنائه.

## ما تغيّر

### 1. وحدة البيانات (`update-site/public/app/data.js`)

- نموذج محلي ثلاثي المجموعات فقط: `tasks` و`subjects` و`taskTypes`، سجلاتها تحمل `id` و`updatedAt` وعلامة `deleted` للحذف.
- `normalizeState` و`put` و`remove` و`mergeRemote` دوال نقية تعمل في المتصفح وفي Node للاختبار.
- **النوتة وملاحظات المهام ومعرّفات الجهاز والتثبيت وPush Token واسم العرض لا تدخل النموذج أبدًا**؛ أي حقل غير مسموح به يُسقط قبل الحفظ أو الإرسال.
- عند السحب يفوز السجل الأحدث بـ `updatedAt`، وعند التساوي يُبقى سجل الخادم (المخزّن)، تماشيًا مع قاعدة الخلفية.

### 2. الواجهة (`update-site/public/app/index.html` + `app.js`)

- صفحة `dir="rtl"` بعناصر تحكم كبيرة، وتخطيط عمودين للشاشات العليا وعمود واحد للجوال، مع مظهر فاتح/داكن محفوظ محليًا.
- إضافة مهمة بالاسم فقط والدقائق والتصنيف اختيارية، وإضافة مادة ونوع مهمة، وحذف أي سجل كعلامة حذف (tombstone).
- بطاقة حساب اختيارية: `profileId` وكلمة المرور، وأزرار «تفعيل المزامنة» و«سحب» و«دفع» عبر `POST /api/sync`.
- كلمة المرور تبقى في حقل الإدخال فقط؛ **لا تُحفظ في `localStorage` ولا تُرسل إلا في جسم الطلب**. الرسائل لا تعرض قيمة الكلمة ولا المعرّف.
- حالة الطلب تُعرض بالعربية، وتتعامل مع غياب الاتصال أو رفض الخادم دون كشف تفاصيل حساسة.

### 3. التكامل الإضافي

- رابط «تطبيق الويب» أُضيف إلى الصفحة الرئيسية دون تغيير سلوكيها الحالي.
- `sw.js` صار `v2` ويُضمّن ملفات التطبيق وصفحة الخصوصية في القشرة دون تخزين `/api/*` مؤقتًا.
- `privacy.html` (مسودة) صُحّحت لتصف المزامنة الاختيارية بدل نفي وجود حساب/سحابة، وتوضّح أن النوتة والمعرّفات لا تُرسل.
- `npm run test:web`: ٦ اختبارات محلية للنموذج.

## التحقق

- `npm run test:web`: ٦/٦؛ `npm run test:sync`: ١٠/١٠؛ `npm run test:targeting`: ٢٢/٢٢.
- `npm run check` + `npm run build`: ناجحان؛ `node --check` لملفات الويب الجديدة والمعدّلة ناجح.
- `git diff --check`: لا أخطاء محتوى (تحذيرات EOL فقط مطابقة لإعداد المستودع).
- **تحقق متصفحي محلي**: خادم ثابت محلي + فتح الصفحة؛ ظهرت الواجهة بلا أخطاء console، وأُضيفت مهمة بالاسم فحُفظت وعُرضت، ثم حُذفت، وتبدّل المظهر، ووُجد رابط «تطبيق الويب» في الصفحة الرئيسية. التحقق كان على `http://127.0.0.1` فقط؛ لا نشر حي.
- `testDebugUnitTest` و`lintDebug` من الشريحة الأولى ما زالا ١٨٦/١٨٦ وبلا أخطاء (لم يتغيّر Android).

## الخصوصية والتوافق

- البيانات المحلية في المتصفح تحت مفتاح جديد `monazem-web-v1`، منفصل تمامًا عن تفضيلات Android وقاعدته؛ لا تغيير في `DB_VERSION` أو الإصدار `0.29.0 / 37`.
- لا أسرار في الكود أو الالتزام؛ لا رموز Blob ولا كلمات مرور ولا معرّفات جهاز.
- لا Supabase ولا Push Token ولا FCM ولا طلب لأي رمز يدوي من المستخدم.

## مؤجَّل صراحةً

- **اقتران الحساب من Android**: لا توجد طريقة داخل تطبيق Android بعد لإنشاء كلمة المرور أو عرض `profileId`؛ المستخدم يحتاج تهيئة الحساب من واجهة الويب أولًا. هذا أكبر اعتماد متبقٍ قبل وصف Phase 6 بأنها مكتملة.
- واجهة إدارة الحساب (تغيير/إلغاء كلمة المرور). (تقييد المعدل على `register` نُفِّذ في شريحة ٥.)
- مزامنة `goals` و`skills` والتفضيلات؛ مراجعة سياسة الخصوصية قانونيًا قبل أي نشر؛ وصول PWA فعلي على جهاز/متجر `Not Verified`.
- لا نشر ولا دفع ولا بناء APK في هذه الشريحة.

## التراجع

`git revert` لكوميت الشريحة؛ ملفات `public/app/` مستقلة، وتعديلات `index.html` و`sw.js` و`privacy.html` مضافة ويمكن عكسها وحدها.
