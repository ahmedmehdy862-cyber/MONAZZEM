# ADR 001 — خلفية تطبيق الويب والمزامنة

> التاريخ: ٢١ نوفمبر 2026 · الحالة: **مقبول** · الفرع: `phase6-web-sync-foundation`

## السياق

تنصّ Phase 6 في Master Prompt على «المصادقة والاتصال الآمن بـSupabase» و«المزامنة مع Android». كان القرار الثابت للمشروع حتى Phase 5 هو «Vercel Blob فقط، بلا Supabase، وبلا Vercel function جديدة». في ٢١ نوفمبر 2026 منح المستخدم موافقة صريحة على **تجاوز قيد Functions فقط** لإتاحة المصادقة والمزامنة، مع بقاء كل القيود الأخرى.

يضع تقرير الـ audit (`MONAZZEM_MASTER_AUDIT_0.29.0.md`) هذا الاختيار كـ «البوابة ٠» ويشترط موافقة صريحة قبل Phase 6؛ هذا المستند هو تلك الموافقة موثّقة.

## القرار

| البند | القرار |
|---|---|
| التخزين | **Vercel Blob الحالي** (`BLOB_READ_WRITE_TOKEN`) في مسارات خاصة جديدة تحت `focus-study/`. لا Supabase ولا قاعدة بيانات جديدة. |
| الدوال | **دوال Vercel جديدة مضافة** في `update-site/api/` (حالياً: `api/sync.js`). لا تعديل على دوال الرسائل أو التحديث القائمة. |
| المصادقة | `profileId` الذي يصدره الخادم أصلًا هو مفتاح الحساب. كلمة مرور مزامنة يختارها المستخدم تُخزَّن كـ `scrypt` مع ملح عشوائي في Blob خاص. المقارنة بـ `timingSafeEqual`. لا Supabase Auth، لا رموز دفع، لا أسرار في العميل. |
| منع التعداد | `pull`/`push` يُرجعان نفس الخطأ `invalid_credentials` لحساب غير موجود أو كلمة خاطئة. `register` يرفض أي `profileId` غير موجود في سجل المستخدمين الحالي. |
| مفتاح الهوية | `profileId` (UUID صادر عن الخادم) فقط. **لا** يُستخدم اسم العرض ولا معرّف التثبيت ولا معرّف الجهاز ولا Push Token كمفتاح. لا يُطلب من المستخدم نسخ أو إرسال أي من ذلك. |
| نطاق المزامنة (الشريحة الأولى) | `tasks` و`subjects` و`taskTypes` فقط، بحقول مسموح بها صراحةً وبطابع `updatedAt` لكل سجل. |
| المستبعد صراحةً | محتوى **النوتة** (`notes`) — محلي/خاص ولا يُرسل لأي خادم؛ أيضاً ملاحظات المهام، سجل الرسائل، صندوق الدعم، الإشعارات، وأي معرّفات جهاز أو أسرار. |
| التعارض | `updatedAt` الأكبر يفوز لكل سجل؛ عند التساوي يُبقى السجل المخزّن (قرار حتمي). الحدف يُمثَّل كـ tombstone عبر `deleted: true`. |
| النقل | HTTPS فقط، `Cache-Control: no-store` على كل استجابة، ولا تُسجَّل كلمة المرور أو الحمولة في السجلات. |

## البدائل المرفوضة

- **Supabase**: يخالف القرار الثابت ويضيف خدمة وأسرارًا جديدة؛ لم يعد مطروحًا بعد موافقة المستخدم على توسيع Vercel.
- **معرّف التثبيت أو اسم العرض كمفتاح**: الاسم ليس فريدًا، ومعرّف التثبيت مرتبط بجهاز واحد؛ كلاهما مرفوض قاعدةً.
- **بثّ عام للمزامنة**: أي مزامنة يجب أن تكون خاصة بحساب واحد؛ لا يوجد fallback جماعي.

## المخاطر والمؤجَّل

- تقييد المعدل (rate limiting) على `register` كان خطرًا مفتوحًا في وقت هذا القرار؛ نُفِّذ في شريحة ٥ من المرحلة 6 عبر `lib/sync-rate-limit.js`.
- كلمة المرور تُخزَّن بـ scrypt، لكن الاستيلاء على `profileId` قبل أصحابه يسمح بادّعاء الحساب أول مرة؛ يُخفَّف ذلك بعشوائية المعرّف ويجب معالجته صراحةً قبل النشر العام.
- الدمج على مستوى السجلات حتمي، لكن ملف Blob يُكتب كنسخة كاملة؛ دفعات متزامنة جدًا قد تفقد إحداهن، ويُعالج ذلك مع تقييد المعدل في شريحة لاحقة.
- واجهة الويب نفسها، واقتران الحساب من Android، وربط `goals`/`skills`/التفضيلات، وPWA، كلها **مؤجلة** لشرائح لاحقة داخل Phase 6.
- لا نشر ولا رفع إصدار في هذه الشريحة؛ الكود محلي ومُختبر مخبريًا فقط.

## التوافق

- لا تغيير في أسماء مفاتيح التفضيلات أو قاعدة بيانات Android أو `DB_VERSION` أو الإصدار `0.29.0 / 37`.
- لا حذف أو تعديل لدوال `messages` أو `latest` أو لوحة الإدارة.
- التراجع: `git revert` لكوميت المرحلة؛ المسارات الجديدة لا تقرأ إلا سجل المستخدمين الحالي للتحقق من وجود الحساب.
